# DOKUMENTASI TEKNIS RINCI: ARSITEKTUR WA BLAST SYSTEM

Sistem ini dirancang untuk beroperasi pada skala raksasa (Enterprise-grade) dengan fokus mutlak pada efisiensi memori, stabilitas koneksi jaringan, dan keamanan logika konkurensi (Anti-Bentrok Data).

## 1. STACK TEKNOLOGI
- **Frontend**: Next.js (React), TailwindCSS (Sistem UI/UX Premium, Glassmorphism, Responsive Mobile).
- **Backend**: Node.js (Express), Prisma ORM.
- **Engine WhatsApp**: @whiskeysockets/baileys.
- **Database**: MySQL.

## 2. ARSITEKTUR WHATSAPP (BAILEYS ENGINE)
Sistem ini memotong pemborosan (overhead) memori secara ekstrem dengan melakukan tuning spesifik pada engine `@whiskeysockets/baileys`. 
- **Tanpa In-Memory Store:** Sistem secara tegas TIDAK menggunakan inisiasi `makeInMemoryStore()`. Artinya, server Node.js tidak akan pernah menyimpan satu byte pun riwayat chat, list kontak, atau status WA ke dalam RAM server. 
- **Kapasitas Skala Besar:** Arsitektur ultra-ringan ini memastikan bahwa satu buah Virtual Private Server (VPS) berspesifikasi standar (ex: 4 vCPU, 8GB RAM) mampu memelihara lebih dari 200 koneksi soket WebSocket secara paralel dan stabil tanpa resiko mati mendadak akibat kehabisan memori (Out-of-Memory / OOM Killer).

## 3. MEKANISME BYPASS PESAN INTERAKTIF (ANDROID FIX)
Untuk memecahkan kebuntuan perihal fitur pesan interaktif (tombol klik) yang kerap diblokir (tidak muncul / tulisan "message couldn't load") pada klien WhatsApp versi Android terbaru, backend menggunakan teknik "Manual Binary Node Injection". 
Sesaat sebelum `relayMessage` dikirim melalui socket, sistem menyuntikkan node buffer/XML rahasia (`tag: 'biz'` dan `tag: 'bot' attrs: biz_bot='1'`) serta merubah protokol internal menjadi `mixed v:9`. Konfigurasi level-rendah ini menipu *security filter* Meta, memaksa server WhatsApp menganggap pesan ini legal secara format, sehingga tombol Native Flow (CTA Url) selalu muncul dengan garansi 100% di semua device Android.

## 4. SISTEM CONCURRENCY TARGET (ATOMIC UPDATE MySQL)
Dengan 200+ mesin (device) yang menembak bersamaan (multithreading-like), terdapat potensi maut bernama "Race Condition" di mana 2 mesin atau lebih berebutan dan mengeksekusi nomor target yang sama di milidetik yang sama. Masalah ini dikunci total dengan **Atomic Update Database**:
- Ketika mesin mengekstrak tumpukan nomor dengan status `READY`, ia tidak langsung memegangnya. Ia dibungkus oleh transaksi Prisma `$transaction`.
- Sistem lalu memaksa sebuah instruksi atomik `updateMany`: `WHERE id = [target_id] AND status = 'READY'`.
- Mesin MySQL Database bertindak sebagai wasit absolut. Ia secara otomatis menggunakan metode "Row-Level Locking". 
- Hanya 1 perangkat pertama (yang masuk lebih cepat 1/1000 detik) yang akan diberi lampu hijau berupa balasan `updateCount: 1` (Sukses).
- Ratusan perangkat lainnya yang telat masuk akan membentur dinding karena status sudah bukan `READY` lagi, dan mereka mendapat balasan `updateCount: 0`.
- Perangkat yang kalah `(0)` diprogram untuk seketika melakukan iterasi (lompat) merampas antrean nomor berikutnya tanpa *crash*.
- **Hasil:** Skema ini menjamin keakuratan absolut; 1 nomor target mustahil menerima lebih dari 1 tembakan, sekeras apapun 200 mesin server ini saling bertabrakan.

## 5. TEMPLATE ENGINE & ALGORITMA ANTI-SPAM
Pesan dikonstruksi secara dinamis hanya beberapa milidetik sebelum pelatuk ditarik. Sistem memiliki mesin filter Regex (`.replace`) tingkat lanjut untuk mengubah string `{{name}}` menjadi array sapaan tak terduga (Kak, Bunda, Bosku, Gan, Sis, dll), dan `{{phone}}` menjadi nomor tujuan. 
Rotasi kata dinamis ini bukan cuma perihal UX (User Experience), melainkan merupakan taktik teknis "Anti-Spam Algorithm". WhatsApp memblokir akun yang mengirimkan *hash byte* string pesan yang sama persis secara berulang. Mengacak bagian string di setiap pesan menjamin keunikan sidik jari pesan tersebut, menjaga usia hidup sesi WhatsApp menjadi jauh lebih awet.

## 6. SIKLUS LOOP & MANAJEMEN STATE (PENDING / TIMEOUT)
Sistem memiliki State Manager yang mengatur sirkulasi darah masing-masing dari 200 mesin tersebut melalui mekanisme "Asynchronous While Loop". 
- Loop ini bersandar pada *Non-blocking IO* Node.js.
- Jika database nomor kosong, loop mesin **tidak akan bunuh diri** atau mengeluarkan *error*. Sebaliknya, ia transisi ke *state* siaga `PENDING (Menunggu Data)`. Ia tidur selama 5 detik, bangun untuk mengecek database, lalu tidur lagi, sembari mengirimkan angka indikator Countdown Timer secara *real-time* ke Frontend/UI.
- **Smart Kill-Switch (Timeout):** Terdapat argo waktu yang berjalan di latar. Jika mesin terjebak dalam masa PENDING melebihi batas toleransi 2 Menit (120 detik) tanpa adanya injeksi nomor baru, mesin akan memutuskan siklus berputarnya secara sukarela (`STOPPED / TIMEOUT`). Ini secara drastis memangkas beban CPU dan IOPS Disk dari VPS, menjadikan sistem sangat ramah dan efisien terhadap infrastruktur.

PROJECT: TRYWSBLAST – WHATSAPP BLAST DISTRIBUTION SYSTEM

Halo, saya ingin membangun sistem web bernama TRYWSBLAST dengan konsep distribusi otomatis untuk pengiriman WhatsApp. Berikut adalah penjelasan sistem secara menyeluruh:

---

1. KONSEP UTAMA

TRYWSBLAST adalah platform web publik dimana user dapat login dan menghubungkan (pairing) satu atau lebih akun WhatsApp mereka.

Sistem akan secara otomatis mengirim pesan ke daftar nomor target yang telah disediakan oleh admin.

User tidak perlu memasukkan nomor target atau pesan, karena semua dikontrol oleh sistem.

---

2. FITUR UTAMA

A. MULTI WHATSAPP SESSION

* 1 user dapat menghubungkan banyak akun WhatsApp
* Setiap akun berfungsi sebagai sender (worker)

B. DISTRIBUSI NOMOR OTOMATIS

* Semua nomor target berada dalam 1 database pusat
* Setiap session WhatsApp mengambil nomor secara otomatis
* Nomor yang sudah digunakan akan berubah status
* Tidak boleh terjadi pengiriman ganda (double)

C. SISTEM ANTI DOUBLE

* Saat nomor diambil → status berubah menjadi "processing"
* Setelah berhasil → status "sent"
* Jika gagal → status "failed"
* Nomor yang sudah dipakai tidak bisa diambil ulang oleh session lain

D. AUTO SENDING SYSTEM

* Pengiriman berjalan otomatis
* Bisa menggunakan limit (misalnya 100 pesan)
* Bisa juga unlimited sampai data habis

E. DASHBOARD USER

* Pairing WhatsApp (QR)
* Start / Stop blast
* Status koneksi WhatsApp
* Statistik pengiriman
* Informasi saldo

F. ADMIN PANEL

* Input / edit pesan blast
* Upload database nomor target
* Monitoring aktivitas user
* Monitoring pengiriman
* Approve / reject withdraw

G. SALDO & WITHDRAW

* Setiap pesan terkirim menghasilkan saldo
* User dapat melakukan withdraw
* Admin menerima notifikasi (Telegram)

---

3. TEKNOLOGI YANG DIGUNAKAN

Backend:

* Node.js (Express atau NestJS)

WhatsApp Engine:

* Baileys (support multi session)

Frontend:

* React atau Next.js

Database:

* MySQL atau PostgreSQL

Queue System:

* Redis + BullMQ

Deployment:

* VPS (Ubuntu)
* Process manager: PM2

---

4. ARSITEKTUR SISTEM

Frontend (User & Admin)
↓
Backend API (Node.js)
↓
Queue System (Redis)
↓
Worker (WhatsApp Sessions)
↓
Database

---

5. FLOW SISTEM

6. User login

7. User pairing WhatsApp (bisa lebih dari 1)

8. User klik start

9. Sistem mengambil nomor dari database

10. Nomor langsung dikunci (processing)

11. WhatsApp mengirim pesan

12. Status berubah menjadi sent / failed

13. Sistem terus berjalan sampai limit tercapai atau dihentikan

---

6. CATATAN PENTING

* Sistem harus mendukung banyak user dan banyak WhatsApp
* Tidak boleh terjadi double pengiriman
* Harus ada delay/random untuk menghindari banned
* Sistem harus scalable dan stabil
* Distribusi nomor harus otomatis antar session

---

7. NAMA SISTEM

Nama aplikasi/web: TRYWSBLAST
